# 0161 — Public Inspector filters preserve exact authority

Status: accepted; bounded clean-platform implementation, deployment verification pending.

An authorized public read is not only inspectable: its exact publisher, facet, entity or value may become an Inspector Filter pill. Extend the existing Filter collection and graph traversal instead of introducing a new query language or copying foreign data into owned Context. Public filters persist publisher/record identity pairs and display labels only. They remain distinct from owned entity/app Quick Links and from binding, placement, mutation and protected-sharing authority.

Public surfaces always expose Add to filters; this action explicitly selects Filter mode and retains other pills. Each public graph retains its exact publisher-to-filter connectors, connectors between its own filter peaks, outward descendants and predicate occurrence points. Unrelated public branches are excluded. No edge is fabricated between requester and publisher. Equal labels or local record IDs across different publishers cannot merge filters or focus.

The existing browser public-inspection store maintains bounded filter views separately from the active query view. Up to sixteen saved references, deduplicated by publisher for transport, reuse the existing authenticated exact-publisher profile hydration API. Only authorized bounded public payloads enter memory. Entry/reload, visible-window focus and sixty-second visible rechecks hide prior payloads before authorization; failure or revocation cannot fall back to old query/discovery data or namesakes. Removed references and account changes invalidate in-flight results. A profile rename may make a saved reference unavailable rather than silently retargeting it.

Unavailable pills remain disabled and removable, preserving restrictive intent instead of silently deleting filters and widening the scene. Reload derives fresh authorization from exact saved references; it does not restore graph payloads from disk. Later queries cannot erase saved filter publishers. Existing bounds remain sixteen pills, 200 entities/400 relations per read and 28 total peer scene points shared across publishers. A record outside that window can remain unavailable. Private/shared graph hydration, protected access, cross-device persistence, immediate revocation push, unlimited paging and production-scale load proof are not implied.

This supersedes the public-filter exclusions in decisions 0147 and 0160 while retaining their read-only and local-first boundaries. No API schema, server table or execution primitive changes. Ordinary offline questions and owned rendering remain independent of the optional lazy public helper.

Source decision: `onevar-platform/docs/decisions/0103-public-filter-pills-revalidate-exact-publisher-graphs.md`. Tests cover exact bounded persistence, predicate witnesses, same-label/same-ID publisher separation, selected focus, query replacement, reload, revocation, offline failure and stale responses. The isolated browser acceptance adds public cats/descriptor filters, two publishers, mixed owned/public scope and zero reader publication/model calls.
