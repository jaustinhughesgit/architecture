# 0158: Typed intent learning and witnessed summary projections

- Status: Accepted, implemented bounded slice; release evidence in capability catalog
- Date: 2026-09-12
- Implementation: `onevar-platform`, decision 0100

The grey-area gap between a recognized Path and existing graph primitives does not require a new arbitrary-code subsystem. Extend the current adviser request with `tier: intent`, selecting one existing typed assertion or read program. Known local Paths, composable description fragments and authorized apps retain precedence. The lexical question hint can narrow a request but cannot prohibit a complete validated read pattern. Unfamiliar wrappers are learned as complete anchored syntax, not added to a source-code word list. Explicit query/composition tiers retain version agreement.

The ordinary input and generic contracts go to the configured adviser with no graph, protected payload or answer authority. Schema/policy/grounding, exact local bindings and the selected interpreter control execution. Read programs cannot write or create missing references. Server-created immutable definitions become shared only after exact creator acknowledgement following browser proof/persistence; another user rebinds their own IDs and facts. This is typed proposal selection, not proof that the model always understood the sentence.

For natural summaries, use a bounded read-side inversion of installed assertion programs. Every link, property, type and occurrence must join current owner-local witnesses. The original pattern supplies grammatical connectors; versioned presentation data supplies speaker/listener perspective. Historical utterances and model-generated answer prose are not truth sources. Missing event context cannot be supplied by another event or a relationship facet. Full-sentence rendering requires all witnesses within the existing description trace bounds; incomplete projections fall back to neutral exact-fact wording. This slice is speaker-rooted, excludes old selected-focus assertions, and preserves existing direct descriptor/count/possession templates. It is not universal narrative generation.

The public/private header button is a trusted UI gesture into the existing ordinary `context.audience.set` command and serialized authorized publication flow. It reports pending or failed confirmation, supports reversal and keyboard activation, and restores persisted audience on reload. Public ordinary Context does not publish protected keys/assets/grants or grant another owner write authority.

If a retried publication acknowledges an older snapshot, the existing queue now drains any newer dirty local revision. A visibility reversal or fact change cannot remain stranded behind the old idempotency receipt; server confirmation still requires the latest revision acknowledgement.

General growth remains **Partial**. No new interpreter primitives, arbitrary source execution, general negation/uncertainty, cross-user plaintext access, or 95% success claim is introduced. Deterministic, full browser, live development and release evidence must be distinguished; see the implementation's `docs/testing/intent-and-summaries.md` and capability catalog.
