# 0159 — Public identity is resolved before answer availability

Status: accepted — bounded clean-platform implementation; general resolution remains Partial.

For ordinary public reads, this supersedes decision 0116's answer-path-first selection. A matching fact may establish answer availability but does not identify the person meant. Known exact identities cannot silently fall back to namesakes after privacy changes, deletion or missing facts.

Ambiguous names enter an identity-scoped conversation: ask how the requester knows the person, filter on explicitly supplied public identifying details, and confirm the narrowed exact identity. Up to four clues are retained for the original read; yes/no, numbered confirmation, start-over, cancel and exact entity IDs are supported. A rejected clue does not become a fact. The browser stores a bounded thirty-minute tab continuation and successful account/role-scoped identity memory. Permission and freshness are revalidated independently.

The existing Sentence Path matcher consumes versioned clarification-language data. The existing hydration API returns one authorized ordinary publisher view, and the existing description primitive projects witnessed counts and details from it locally. Names, lexical clues, stored memory, model outputs and display positions grant neither read nor write authority. Protected plaintext never enters this channel. Ordinary data owned by a known local person is not silently equated with a public account bearing the same name.

Current scope is plain/composed count questions, description Paths, and the prior current-state hydration path. A fresh public read is limited to 200 entities/400 active relations. Name retrieval uses 64 shards with bounded reads and refuses an incomplete shortlist; exact IDs bypass fan-out. Public clue matching follows bounded directed graph evidence, not inferred social identity. General learned-query hydration, unrestricted paraphrases, requester-only social evidence, six-degree ranking, larger graph projection/paging and million-user quality/load proof remain Partial. Protected-recipient, relay and conference clarification retain their prior separate behavior.

The canonical machine schemas and executable evidence live in `onevar-platform`; see its decision 0101, `services/api/src/public-read.test.ts`, `referent-resolution.test.ts`, `tests/browser/public-referent.spec.ts`, and `docs/testing/public-identities.md`. Deployment must not reset shared test data.
