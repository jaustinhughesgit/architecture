# 0200 — Shared endpoints and explicit reference correction

Status: Implemented bounded clean-platform slice; local verification, not deployed.

Inspector's story index groups active references to an exact ordinary endpoint
by distinct owner-local non-structural object subjects. People, places and typed
times reuse the existing ring/count, paged previews, full-story navigation and
combined popup. Exact IDs, authority and independent stories remain unchanged.
Namesakes and spelling resemblance never supply identity. The primary owner
retains its solar-anchor role; no blanket promoted/user exclusion is introduced.

For older data, a personal ordinary worker preview can correct one condition
reference to an explicitly chosen existing compatible entity, or normalize one
old time with its original observation date and a confirmed original timezone.
The preview expires in five minutes and any snapshot/permission/publication change
requires another preview. Missing historical evidence never falls back to today.
Confirmation updates the existing relation version and appends an observation,
preserving original entities and unrelated facts, then uses ordinary local
persistence, receipts and canonical publication. Existing sharing rules remain.

This is not destructive merging, global alias learning or a bulk migration.
Existing identity properties still provide lexical aliases. Correction of managed,
peer and protected data is outside this personal route. No new server access,
Compute/JPL behavior, stored entity schema, or model call is introduced.

Implementation and regression evidence: clean-platform decision 0148 and
`context-correction`, Inspector scene tests, and desktop/mobile semantic browser
fixtures. General semantic identity resolution remains Partial.
