# Reverse ordinary queries are exact local reads

Accepted 2026-09-11.

The clean-room ordinary graph interpreter supports one bounded `graph.query` operation for reverse descriptor and recorded-count lookup. Language-package terms compile into typed conjunctive filters; exact current ordinary relations supply answer subjects and versioned witnesses. Quantities compare numerically in count roles, while plural forms remain lexical addresses rather than identity merges. A descriptor does not propagate through ownership, and an explicitly managed collection does not imply possession.

The initial scope is currently owner-local ordinary data. Every active witness and endpoint, including a facet, must satisfy that boundary before matching. Hydrated/foreign data and protected assets remain outside it. The result includes at most eight exact subjects and the total match count. Display uses bounded exact owner paths, preserves namesakes, and describes no-match as absence from recorded facts rather than universal truth.

Queries execute before Path archive/adviser discovery and never mutate Context, observations, publication state, or conversational references. One reusable core query Path identity records varying typed plans in local interaction evidence. Query result IDs remap during canonical acknowledgement without adding the answer to graph publication. The schemas belong to the shared contracts and ordinary worker/review boundary; no server data-access or execution authority is added.

Implementation details and regression boundaries are in `onevar-platform/docs/decisions/0095-reverse-ordinary-queries-follow-exact-current-facts.md`. This is an implemented bounded extension of the **Partial** composed-language capability, not proof of general query understanding or 95% arbitrary-language coverage. Negation, temporal/comparative/location filters, cross-user queries and inferred members remain outside this slice.
