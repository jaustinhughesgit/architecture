# 0148 — Named possessions use one exact identity object

Status: accepted.

## Context

The clean runtime represented `My friend's name is Tom` as a generic `friend` object with a separate visible name value. A broad active learned Path could intercept the later core declaration `I have a friend named April`, and compound `my friend April` references retained grammatical owner language as if it were identity evidence. The graph consequently obscured the intended subject and could not add another same-kind named object.

## Decision

Trusted core named-possession grammar creates or identifies one exact owned object in one local revision. `My {kind}'s name is {identity}` may materialize its missing subject and retain `{kind}` as classification. `I have|own a {kind} named|called {identity}` always creates a new exact object rather than selecting a same-kind object. Recognized core grammar precedes ordinary learned-template dispatch; isolated Path proof explicitly selects only the candidate under proof.

An already owner-scoped reference may discard one grammatical leading `my`, after which every remaining kind and identity token must address the same exact object. Equal candidates still clarify. A core count question uses the existing current-property query over that resolution; names remain lexical evidence rather than authority.

Inspector V2 projects the strongest active `name`, `nickname`, `alias` or `callsign` as the label of that same exact subject ID and folds a terminal identity value into its detail surface. Kind and identity facts remain inspectable. Existing property-shaped name graphs require no persistence migration, and values with any other semantic use or outgoing relationship remain independent.

## Consequences

Tom and April remain two exact owned entities even though both have kind `friend`; facts about either cannot mutate the other. Historical active learned Paths cannot shadow known ownership declarations or count queries. This adds no server authority, protected-data path, identity merge, nested ownership inference or unrestricted language coverage. Implementation proof is owned by `onevar-platform` decision 0090.
