# 0160 — Public query results are read-only Inspector peers

Status: accepted; bounded clean-platform implementation deployed and live-verified in development.

A successful authorized public read must be inspectable even when its publisher shares no ambient discovery facets with the reader. The browser hands the exact already-authorized hydration slice to a separate, read-only public Inspector projection. It does not import the publisher's entities into the reader's owned graph, infer a social link, repeat ambiguous name selection or widen protected access.

One active query view is bounded by the existing 200-entity/400-relation public read contract and 28-peer scene budget. The queried publisher and its exact neighborhood outrank ambient peers; exact relation and facet IDs drive expandable straight connection chains and fact surfaces. Solid-bordered, dark-filled points distinguish authorized other-user data; dashed, disconnected points distinguish marketplace suggestions. Styling is not an access grant.

Only a thirty-minute, account-scoped tab reference persists: exact publisher, profile/object references, scope and expiry. Graph payloads and layout coordinates remain memory-only. Inspector entry/reload, visible-window focus and a sixty-second visible-view interval revalidate the exact publisher through the existing authenticated hydration API. Hide payloads while checking and on failure. Revocation/mismatched identity clears the view and reference without trying namesakes. Passive refresh cannot extend expiry. Generation checks discard late results after replacement/account change. Remote revalidation is bounded polling, not instantaneous permission-change push.

Ordinary local interpretation and owned/offline rendering do not depend on loading the public-view helper. Explicit filters still exclude unrelated peer results; normal Inspector navigation remains a presentation lens, not authority. Public points cannot be bound, placed or mutated through owned-data controls. Existing protected-recipient authorization remains separate.

Inspector V1 and its selector are removed. The reusable V2 spatial geometry and loading shell remain; legacy V1 preferences are ignored. V2 is the only active Inspector, with an informational bottom-left label and the existing CLI toggle. No V3 migration is introduced. This supersedes the selectable-V1 lifecycle in decisions 0135 and 0147, not their historical release evidence.

This repairs the rendering gap left by decision 0159's isolated publisher reads. It adds no API/table or language subsystem and does not claim unrestricted public query hydration, paging beyond the bounded view, million-user load proof or 95% language coverage.
