# Capability Catalog

This catalog prevents future work from assuming a capability is absent merely because it is unfamiliar. It is intentionally incomplete and must grow as the platform is inspected and discussed.

Legacy fields remain compatible, and complete modality/accessibility adoption is unfinished. |
| Browser-local input rollback | Implemented foundation | `aws` | Message Back restores a bounded, identity-scoped pre-input checkpoint across graph/ContextDB, history, local translations, word map, and learned Path library. Server Path reconciliation is asynchronous. External effects and protected-asset use are not reversible. See [decision 0014](../decisions/0014-browser-local-input-rollback.md). |

Quantity and event-count migrations replace nineteen active sentence-shaped equations with four composed Paths, including coordinated entity-set quantities; one additional self-property composition handles `my <property> <copula> <value>`, for a merged foundation of 16 installed Paths. Server replication is byte-bounded, preserves splittable payload-size errors, and validates the v4 persistence envelope without moving matching authority out of the browser. Other bundled families remain v3, and content-addressed lazy pack hydration is future work. See [decision 0020](../decisions/0020-compositional-subpattern-capability-framework.md). |

| Browser-local canonical Essence generation | Implemented foundation | `aws` | Installed Paths materialize validated local transforms. | Deterministic Path response sentences | Implemented foundation | `aws` | Every bundled answer-producing question operation carries a catalog-owned template over locally proven query variables and request bindings while preserving the canonical raw answer. Hydration backfills matching existing direct and semantic Paths without overwriting learned presentation. If another successful ordinary Path lacks a template, a resumable model job may propose one over bounded proven variables; server, browser, and Path Builder validation precede installation and current-response use. Voice-originated proven answers become ephemeral Automation speech steps; typed, unverified, and protected results remain excluded. Broader grammar, localization, and offline speech remain future work. See [decision 0016](../decisions/0016-path-response-sentences-from-local-proof.md) and [decision 0017](../decisions/0017-missing-response-templates-use-locally-validated-llm-proposals.md). |
| Data-defined local semantic entities | Implemented foundation | `aws` | Versioned operation templates compile locally with Path bindings. Personal and qualified-owner quantities share signed observation storage. Quantity, participant-event, vocabulary-neutral activity occurrence, relationship transition, direct entity property, entity classification, selected-relation correction, and local trigger/effect policy entities exist. Participant-event assertions retain optional multiplicity; actor counts and typed-participant counts sum that explicit value while treating an unquantified distinct record as one. Role-aware supporting-graph routing can select the participant projection only when executed question/support bindings identify the same entity. Coordinated entity lists preserve canonical identity separately from source display form and can render a natural-language list. Relationship transition separates an observed transition, object/reference identity, and a resulting relationship between distinct objects; its catalog-declared binding constraints reject overlapping or ungrounded semantic roles, and catalog-declared failure routes can redirect repair to a compatible primitive. Direct entity property records one subject-property-value state with optional provenance and typed identity details. Classification can add a broader type to a specific entity without domain vocabulary. Correction provenance/version history, transitive ontology inference, contradictions, state expiration/reversal, and formal contract schemas remain incomplete. |
| Local syntax evidence + LLM semantic adjudication | Partial | `aws` + model services | The browser extracts vocabulary-neutral structural triplet evidence. A cold miss supplies it with bounded recent results and ContextDB to a strict model response containing speech act, answer or graph writes, grounded historical repairs, and Path plans. The complete adjudication is returned to the browser on success and rejection. A separate labeled `interpretation` envelope makes the model answer, explanation, correction status, sanitized response, and usage observable without treating them as locally verified truth. Catalog-declared local-syntax plans can compile typed alternatives for compatible grammatical structures. Catalog-authorized structural-token policies may prove fixed grammar only when their selected operation effect is locally satisfied; ordinary semantic values still require typed bindings. The browser requires every accepted Path to materialize the rows or reproduce the answer atomically; the model has no direct write authority. Compatible installed question Paths are evaluated read-only as a guarded set: one answer-bearing semantic interpretation wins, while multiple valid interpretations fail closed and their bounded evidence reaches repair. Repeated identical deterministic failures stop further model escalation. Contradiction policy, user-facing ambiguity confirmation, and broad cold-domain evaluation remain incomplete. See [decision 0012](../decisions/0012-llm-semantic-adjudication-to-locally-proven-paths.md), [decision 0015](../decisions/0015-visible-llm-interpretation-with-local-proof.md), and [decision 0018](../decisions/0018-catalog-authorized-structural-evidence-in-path-repair.md). |

Semantic Plan v2 accepts role sources/spans without model-authored runtime value modes when an operation publishes `bindingSchemas`; catalog defaults, dependencies, and source policies complete the binding contract. Versioned support-binding derivations can expand one query plan into an atomic historical-repair/query transaction. Rejections identify interpretation, compiler, catalog, or validation ownership so deterministic compiler/catalog defects do not consume more model correction rounds. Declarative non-catalog Essence Paths remain available when no installed operation faithfully represents the adjudicated graph, subject to browser validation. Broader binding-schema adoption, automatic versioned capability induction, and complete capability-gap remediation remain work. See [decision 0011](../decisions/0011-typed-semantic-plan-path-synthesis.md) and [decision 0019](../decisions/0019-semantic-role-plans-use-catalog-binding-schemas.md). |

## Adding a capability

When a capability is found or proposed, record:

1. User and builder value
2. Owning primitives and layers
3. Current evidence in code or tests
4. Trust and authorization boundary
5. Lifecycle and versioning
6. Known gaps
7. Whether it supersedes or generalizes another entry
